:::meta description: Luccet is a document format with the full power of HTML, CSS and JavaScript and none of HTML's verbosity: one file that renders itself in the browser. ::: ::site-nav ::logo # Luccet {#top} ::toc **Luccet gives you the full power of HTML, CSS and JavaScript without the verbosity of HTML.** A note is one HTML file that renders itself: its first line loads `luccet.js`, and everything below it is written in a light, Markdown-like syntax that the browser turns into real HTML when the file is opened. ## A first note {#first-note} This line is all the setup a note needs: ```html ``` Everything after it is the note. Save the file next to `luccet.js`, open it in a browser, and it renders: ```luccet {.live} # Hello This is a note. It has *emphasis*, a [link](https://example.com), a formula, $e^{i\pi} + 1 = 0$, and a key to press, :kbd[Ctrl]+:kbd[S]. - [x] Write the first line - [ ] Publish it ``` Every example on these pages is live: it shows the source, the result, the HTML Luccet made, and any diagnostics, all computed by `luccet.js` in your browser. ## A tour {#tour} ### Math {#tour-math} TeX between dollars, which Luccet turns into MathML itself: there is nothing to load. A display formula with an id is numbered, and `@id` refers to it. [Math](docs/math.html#top) lists the TeX a formula can use. ```luccet {.live} The roots of $ax^2 + bx + c = 0$ are $$ x = \frac{-b \pm \sqrt{b^2 - 4ac}}{2a}. $$ {#eq-roots} By @eq-roots, a real root needs $b^2 \ge 4ac$. Prices like $5 stay prices. ``` ### Blocks {#tour-blocks} Three colons and a name wrap anything in an element. HTML names become that element; other names become a `div` with the name as its class, ready for your CSS. ```luccet {.live} :::details[Why is the sky blue?] Short wavelengths scatter more: *Rayleigh scattering*. ::: :::aside This is an `
`, because `aside` is an HTML element. ::: ``` ### Numbered theorems {#tour-theorems} A note's vocabulary turns names into numbered, labelled elements. This example uses the demo vocabulary from [the Vocabulary page](docs/schema.html#demo-schema); a note declares its own in one script. ```luccet {.live schema=demo} :::theorem[Pythagoras]{#thm-py} In a right triangle with legs $a$, $b$ and hypotenuse $c$, $a^2 + b^2 = c^2$. ::: :::proof Arrange four copies of the triangle inside a square of side $a + b$. ::: By @thm-py, a triangle with sides 3, 4 and 5 has a right angle. ``` ### Tables {#tour-tables} Pipe tables, with alignment from the colons. ```luccet {.live} | Element | Symbol | Mass | |---|:-:|--:| | Hydrogen | H | 1.008 | | Helium | He | 4.003 | | Lithium | Li | 6.94 | ``` ### Figures {#tour-figures} An image with an id becomes a figure, its bracket text the caption (demo vocabulary, for the number). ```luccet {.live schema=demo} ![Osprey over the estuary, at dawn.](examples/img/osprey.svg){#fig-osprey width=320} @fig-osprey was drawn from memory. ``` ### References {#tour-references} `@id` links to anything with an id, and its text comes from the target: a heading's text, a title, a number. Nothing to keep in sync by hand. ```luccet {.live} ## Results {#results} :::aside[A caveat]{#caveat} The sample was small. ::: See @results, and read @caveat before relying on them. ``` ### Footnotes {#tour-footnotes} ```luccet {.live} Terns are long-distance migrants.[^arctic] [^arctic]: The Arctic luccet's yearly journey, from the Arctic to the Antarctic and back, is among the longest of any animal. ``` ### Grids {#tour-grids} `+++` splits a block into cells, and the block becomes a grid. On a phone, it is one column. ```luccet {.live} :::row{cols=3} **Write** a note in any editor. +++ **Open** it in a browser. +++ **Publish** it on any static host. ::: ``` ## Why Luccet {#why} - **One file.** A note is a single `.html` file next to `luccet.js`. Open it from disk, keep it in a repository, put it on any static host. There is no project to set up. - **No build.** The browser renders the note when it opens. `luccet build` can pre-render a page for search engines, but you never need it to see your work. - **Real HTML out.** Every construct becomes ordinary, accessible HTML: headings, sections, figures, tables, real `` and `
`. Labels such as "Theorem 1" are text, so they copy, print and are found by search. When you need more, HTML, CSS and JavaScript are right there in the note. - **Your vocabulary.** Theorems, callouts, cards or web components: a note names what it needs, and a few lines of schema give the names labels, numbers and behaviour. - **Diagnostics.** Nothing is lost silently. Malformed markup stays visible where you wrote it, and Luccet reports a positioned diagnostic with a hint that spells the fix: ```luccet {.live expect="block.unclosed ref.dangling"} :::aside An aside nobody closed, with a reference to @nowhere. ``` - **A language server.** `luccet lsp` brings the same diagnostics to your editor as you type, with completion of names and ids, go to definition, rename, an outline, and links fixed when you move a file. `luccet check` prints them for a whole folder of notes. ## Get started {#get-started} 1. **Download [`luccet.js`](luccet.js)** and put it in the folder where your notes live. It is the whole engine, with no dependencies. 2. **Start a note.** Write the first line yourself, or let the command line write it with the right path: ```sh node luccet-cli.js new notes/hello.html --title="Hello" ``` 3. **Open the file** in your browser, from disk. Edit, save, reload. A panel in the corner lists any problems while you work. Then read [the Guide](docs/guide.html#top), which goes from the first line to vocabularies, styling and publishing. ## Documentation {#documentation} | Page | What it covers | |---|---| | [Guide](docs/guide.html#top) | a complete tutorial, from the first line to schemas, publishing and the editor | | [Syntax: blocks](docs/syntax-blocks.html#top) | the eight rules, attributes, and every block construct | | [Syntax: inline](docs/syntax-inline.html#top) | every inline construct, the ambiguity rules, escapes | | [Math](docs/math.html#top) | the TeX a formula can use, macros, environments, fonts and browsers | | [Elements and output](docs/elements.html#top) | how names become elements, titles and labels, numbering, references, ids, figures, raw HTML, metadata | | [Vocabulary and behaviour](docs/schema.html#top) | schemas, `window.LUCCET.schema`, add-ons, `luccet.define`, styling, themes | | [Add-ons](docs/addons.html#top) | what an add-on is, and Luccet's add-ons, each in its own repository: code highlighting, diagrams, citations, search, a list of notes, a glossary | | [Diagnostics](docs/diagnostics.html#top) | every diagnostic: when it fires, what happens to the content, the fix | | [Command line and editors](docs/tools.html#top) | `luccet new`, `check`, `parse`, `build`, `mv`, `corpus` and `lsp`; editor setup; a skill for coding agents | | [Publishing](docs/publishing.html#top) | hosting, `luccet build`, CSP, offline use, browsers, trust | | [JavaScript API](docs/api.html#top) | `luccet.*`, the AST, the runtime lifecycle, events, config | ## Examples {#examples} Complete notes, each declaring its own vocabulary in a few lines at the top. These pages and the engine's conformance tests are the reference, and every live example on them is checked against the engine. The engine is at version 2.0.0 (`luccet.version`; the tags on GitHub and jsDelivr carry the same number) and follows [semantic versioning](https://semver.org): a patch release fixes, a minor release adds, and only a major release may break. What a release may not break outside a major: - **Rendering:** the HTML and the diagnostics the conformance corpus records for a note. A fix that changes a case's output is a patch only when the old output contradicted these pages, as a hole in [`safe`](docs/publishing.html#trust) does. - **The API:** the members of `luccet` and their documented behaviour, and what an add-on receives. - **The command line:** its commands, options, exit codes and the shape of its `--json` output. - **The files `luccet index` writes:** read by their `format` number, which changes only in a major release. A minor release may add constructs, options, members, commands, fields in JSON output and in index files (a reader ignores the fields it does not know), and diagnostics at warning or info severity. Not covered: the wording of the command line's messages and of console lines, and the [add-ons](docs/addons.html#top), which have their own repositories and their own versions. Pin a release (`@v2.0.0`) to be sure; `@2.0` follows the fixes of a series. `@2` follows every release of a major, which keeps every note rendering the same; the [changelog](https://github.com/Luccet/luccet/blob/main/CHANGELOG.md) says what each release changed. **Deprecation.** Something that is to go is marked deprecated in the changelog and on its page, and keeps working, with a diagnostic or a console line that names its replacement, until the next major release, which may remove it. Nothing described on these pages is deprecated today. **What 1.0 rests on.** The engine reached 1.0 when its readiness plan was through: the safe-rendering contract complete and documented ([Trust](docs/publishing.html#trust)), the browser floor stated and guarded ([Browsers](docs/publishing.html#browsers)), an npm package, Windows and WebKit in the test matrix, and no open finding of consequence. Luccet is MIT licensed; the source is at [github.com/Luccet/luccet](https://github.com/Luccet/luccet). **AI assistance.** Luccet is developed with the help of an AI coding assistant: it drafts code, tests and documentation under the author's direction. Everything that lands is read and run by the author, and the tests, the conformance corpus and the live examples on these pages are the record of what was verified. A page that reads as if a person wrote it was reviewed by one.
