# Changelog

Every release of Tern, newest first. Versions follow [semantic versioning](https://semver.org): a patch release fixes, a minor release adds, and only a major release may change how an existing note renders, what an add-on receives, what the command line takes and prints, or the files `tern index` writes, after a deprecation announced one minor release ahead. Before 1.0 a minor release could change these, and the entry says so where it did. The engine reports its version as `tern.version`; the tags on GitHub and jsDelivr carry the same number from 0.4.3 on.

## 1.0.1 (unreleased)

- The documentation site can be published between releases: the `site` workflow, run by hand from the Actions tab on `main`, publishes `index.html`, `docs/` and `examples/` from `main` with `tern.js`, `tern.css`, the add-ons and the themes of the newest tag, after the docs and samples suites pass against that engine, so what the site serves to notes that load its `tern.js` stays a release.
- The documentation site: a live example sets its result under its source at every width, where a wide screen set them side by side; the home page's mark is small and stands before its title; the theme switcher is no longer in the site navigation (the add-on itself is unchanged).

## 1.0.0 (2026-10-19)

- Tern 1.0.0. The syntax the documentation describes and the engine carry one number from here on, and the versioning promise above holds without the 0.x caveat: how a note renders, what an add-on receives, the command line and the files `tern index` writes change only in a major release, after a deprecation. The home page's Status section, `SECURITY.md` and this preamble say so; `@1` on jsDelivr follows every 1.x release.
- `search.json` and `glossary.json` carry the number of their format (`"format": 1`, `tern.search.format` and `tern.glossary.format`), and `tern search --index`, the search add-on and the glossary add-on take a file of the format they read whatever version wrote it, where they refused a file from another minor version. The number changes only in a major release. A file with no format, written before 1.0, is refused as before: run `tern index` again.
- `addons/glossary.js`, a glossary: `::glossary` lists the terms the notes of a folder define, from `glossary.json`, which `tern index` now writes beside `notes.json` and `search.json`, each term linked to its definition, with the definition rendered as on its page (its links led back to the note, its formulas typeset by the page's math add-on); `:term[…]` marks a use of a term and links it to the glossary page's entry (`page=` names the page). A term is defined by `:dfn[…]`, HTML's defining instance of a word, whose paragraph is the definition, or by a titled `:::definition` block, whose body is; `tern.glossary.terms` and `uses` are the engine's reading of a note, so the command line and the browser agree. `tern index` says when a term is defined twice or a `:term` has no definition, counts the terms in its summary, and `--check` covers the third file: a hook that stages the files adds `glossary.json`.
- `tern new` writes the guard by default: the first line ends with what shows the note's source, readable and wrapped (`white-space: pre-wrap`), when `tern.js` does not load or JavaScript is off; `--bare` leaves it out, and `--guarded` is accepted and changes nothing. `--lang=TAG` puts `lang: TAG` in the `:::meta` block and the guard's message in that language (German, English, Spanish, French, Italian, Dutch, Portuguese; English otherwise), the tag on the message and the text. The documentation and the skill show the line as written now.
- Search reads other scripts: words are folded (NFKC, lower case, the diacritics of Latin, Greek and Cyrillic letters removed, so `cafe` finds Café in either Unicode form, `istanbul` finds İstanbul, `е` finds ё), a word keeps its combining marks (Devanagari, Thai, Arabic words stand whole), and a run of Han, Kana or Hangul is searched by pairs of characters at index and query time, with no segmenter, so `東京` finds 東京タワー and an index written under Node serves every browser; `tern.search.fold` is the folding. An index from 0.6 is refused as before (its words differ): run `tern index` again. In the search box the arrow keys walk the results and Escape returns to the box.
- `tern build --diagrams` draws the note's `mermaid` fences into the page: the note is opened in a headless Chromium (the `playwright` package, as `--math` needs `katex`) and the Mermaid add-on draws, with Mermaid from the add-on's `?base=` folder, a `mermaid` package, the tool's cache or jsDelivr. A fence gets a copy per palette (light, dark) and a print copy, marked with their palettes; a small stylesheet shows the right one with scripts off; the add-on adopts them on the page and asks for Mermaid only for a palette with no copy (a switched theme). A fence Mermaid cannot draw stays a fence, with a `diagram.error` warning.
- `addons/switcher.js`, a theme switcher: `::themes` is a labelled select of Tern's themes, "Solarized (dark)" (`themes=` for a list of your own, `base=` for another folder, `at=SELECTOR` to put the control in a site's navigation). A choice applies at once, with the old sheet removed once the new has loaded, is kept in `localStorage` and applied before the note renders on every page of the site that loads the add-on. It dispatches `tern:theme` on `window`; `mermaid.js` listens and redraws in the new palette. The documentation pages carry it at the end of the site navigation.
- Tern has a logo: `docs/tern.png` and `docs/tern-white.png`. The README shows it, and the documentation pages carry it in the site navigation and above the home page's title, the white one where the theme's text is light.
- `addons/copy.js` puts a copy button on every fence and listing (`{data-copy=false}` leaves one out): the code as written, without line numbers or highlighting, through the clipboard API or a selection where the page may not use it, with a status line for screen readers; `addons/lightbox.js` opens a figure's image full size in a `<dialog>` on a click or Enter, with its caption, closed by Escape, a click beside it or its button, focus returning to the image (`?images=all` takes every image; `{data-lightbox=false}` leaves one alone). The docs pages load the copy button; the accessibility suite checks both add-ons' controls in every theme.
- `addons/cite.js`, citations: a `:::bibliography` block holds sources in BibTeX or CSL-JSON (or a head script shares them through `window.TERN.bib`), `@key` cites one and reads `[1]`, or `(Knuth, 1984)` with `style=author-year`, and the block lists the cited sources, formatted in one plain style and sorted by author, by first citation or as written. A citation is a reference, so no syntax changes; `tern check` and `tern build` see the same list, and an entry that cannot be read, a duplicate key, a key `@` cannot reach and an empty block are `cite.syntax`, `cite.duplicate`, `cite.key` and `cite.empty` at the entry's line.
- The home page's Status section tells the syntax version (1.0, what the pages describe) from the engine's (`tern.version`, 0.x), and states the 0.x policy: until 1.0 a minor release may change what a note renders or an add-on receives, and the changelog says so when it does; a construct or an API is deprecated for one minor release before it goes. README and the home page say what the AI assistance covers and how every change is reviewed.
- `tern vendor DIR` writes local copies of KaTeX, highlight.js, Mermaid and Temml, the versions the add-ons pin, in the layout their `?base=` option takes, for offline notes and strict policies.
- The engine is an npm package, `@ozkrac/tern`, installed from this repository at a tag (`npm install github:OzkrAC/tern#vX.Y.Z`; it is not on the npm registry): `tern.js` with `tern.css`, the add-ons, the themes, the skill, the `tern` command and type declarations (`tern.d.ts`), with an `exports` map for `@ozkrac/tern/cli/language.js` and the rest the documentation requires. The release carries `tern.css` and a zip of the distribution beside the minified `tern.js`. `test/package.js` keeps the package honest.
- `window.TERN.strings` gives the runtime's and the add-ons' words in another language: the diagnostics panel's counts, the search box's placeholder and status lines, the notes list's label and messages, and the emitter's ARIA labels (`tern.emit` takes them as `opts.strings`). `tern.string(key, params, fallback)` is the hook add-ons use.
- The commands run on Windows: the sandbox speaks over the child's standard input and output and, where the pipe cannot be read directly (Windows), starts one child per note; a link to a file under a folder whose name the disk spells otherwise than the path (a short name such as `RUNNER~1`, a symbolic link such as macOS's `/var`) is no longer `link.missing`, since link checking walks the path as written from the note's folder; every path the commands print uses forward slashes on every platform.
- The smoke suite passes in WebKit: its copy test, which presses Ctrl+C, copies through `document.execCommand('copy')` from that key press there, since Playwright's WebKit shell on Linux binds no key to copy; the handler and the event it answers are the same.
- CI gains a Windows job for the command line and the language server and a WebKit smoke job, advisory (reported, not blocking) until they were green and blocking since, and a coverage report of the Node suites (c8) as a run artifact; the tests and the publishing page say so.
- CI runs one workflow per branch at a time (a push cancels the one before it), seeds the fuzz run from the run id so every run tries new inputs, and on a pull request checks that `CHANGELOG.md` changed, as CONTRIBUTING asks.

## 0.6.0 (2026-10-17)

- `tern.css` and the themes: a new `--t-line-strong` (3:1 against the page) borders `kbd`, the diagnostics panel and the search box; text in a highlight is `--t-fg`, so muted text and links stay readable on it; `prefers-contrast: more` puts muted text in the text colour and rules in the strong line; under `forced-colors` every property takes the system's colour; `--t-size` is `1.125rem`, so a reader's own font-size setting holds. The themes are regenerated with the new property and the two media blocks, and `test/themes.js` checks them.
- The smoke suite runs axe-core (WCAG 2.0 and 2.1, A and AA) over a page of every construct in tern.css and in every theme, light and dark, and finds no violation; the one it found, a link inside a highlight in its link colour, is fixed: text in a highlight is the text colour, a link's too.
- Each GitHub Release carries a minified `tern.js`, under that name so the tools take a note that loads it: the release workflow builds it with a pinned terser, checks the version and a render, and drafts the release with the changelog section as its notes. `tern new --use` writes a `<link rel="preload">` per add-on on the first line, so the browser fetches it alongside `tern.js`.
- A long note paints its first screen without laying out the rest: from 200 000 characters (`tern.config.holdOver`; `0` never holds) the mount holds the top-level blocks out of view with `content-visibility: auto`, as the KaTeX add-on did for math-heavy notes, and releases each before it comes into view, and all before printing or a fragment jump. On a 1 MB note the mount frame's layout went from seconds to tens of milliseconds; the smoke suite keeps it under 1.5 s.
- The search and notes add-ons: the results and the list are `role="list"`, the status line is the one live region, Enter runs the query as typed before it opens the first hit, `limit=0` lists none, and a page without its extension counts as the page itself; `::notes` shows a date that is not `YYYY-MM-DD` as written, without a `<time>`, and sorts it last, and `tern index` says when a note has one. The Mermaid add-on gives a fence Mermaid cannot draw its id back, makes every id in a drawing unique to its placement, and draws the print copy for every palette that is not print's, a light theme's too. The MathML add-on fetches Temml's stylesheet with Temml, at the first formula; KaTeX, Temml and Mermaid are asked for again at the next render when a load failed. The CSP page lists the MathML add-on's `style-src` and `font-src`.
- The emitter's HTML says more to assistive technology: a table's header cells carry `scope="col"`, the footnote section is `role="doc-endnotes"` with an `aria-label`, a footnote reference's link `role="doc-noteref"`, a back link and a task checkbox have an `aria-label`, in the note's label language (seven built in, English otherwise). A fence's `start` sets the custom property `--t-start`, which the stylesheet's line counter reads, in place of a typed `attr()` only Chromium understood; the transform records the label language on the tree as `ast.data.tern.lang`.
- The language server runs a note's code over an asynchronous sandbox bridge, so a script that never returns no longer freezes every document: requests are answered from the last analysis while one runs, a change made meanwhile is analysed after it, and a rename waits for the analysis. A note whose scripts time out or crash keeps the vocabulary of its last analysis until its head or add-ons change. `note.analyseAsync` is the asynchronous form of `analyse`; the commands keep the blocking one.
- The language server follows a link `page.html#id` as a reference: definition goes to the id's declaration in that file (or the element with that id in an HTML file, the heading with that anchor in a Markdown file), references and rename reach the fragment of every such link from the workspace's notes, and `textDocument/documentLink` gives every URL's target. `textDocument/codeAction` offers quick fixes: a near id for `ref.dangling` or its escape, a footnote's definition, a closer for `block.unclosed` and `math.unclosed`, a near name for `name.unknown`, braces for `block.opener-junk`, the disk's spelling for a `link.missing` in another case. `workspace/symbol` searches the headings and blocks of the workspace's notes. `language.idAt`, `declaration` and `actions` are new.
- The language server takes `workspace/didChangeWorkspaceFolders`, asks a client that can watch files to watch notes, what they link to and what they load, and analyses a note again when an add-on it loads changes on disk; what it keeps of the files it read is capped at 512 entries per table, and a file rename reads the notes through the same cache.
- `tern mv --json`, `tern build --json` (the page in the object without `-o`) and `tern index --json` print one object on stdout. A note that is not valid UTF-8, or is UTF-16, is said on stderr by every command that reads it. `tern index` asks git for the dates of the indexed notes alone, and says when a log cut at 256 MB left notes dated by their modification time; the dates were silently lost before. A sandbox process that dies three times in a row before answering trips a breaker for a minute, said once, instead of being started again for every note.
- tern.nvim, the Neovim plugin, takes the new capabilities in its own repository (code actions with `gra`, cross-file definition, references and rename, workspace symbols, and a `watch` option for the server’s file watching), and its own CI runs its tests against Tern’s `main`.
- Completion is triggered by `:` and `@` only (`/` and `#` are typed inside a trigger), and right after a keystroke it reads the trigger from the text as it is, answering from the last analysis instead of running one per trigger. `language.completion` takes the current text as a third argument for that.

## 0.5.1 (2026-10-16)

- A note script that calls `tern.render(el, source)` with a script in the source no longer disarms the `document.write` guard for the scripts after it; a later `document.write` wiped the page.
- An add-on that never loads no longer leaves a blank page: 12 seconds after the note has arrived (`tern.config.addonTimeout`, in milliseconds) the note mounts without it, with `addon.failed`; the console says what is still awaited after 2 seconds; the document carries `aria-busy` until the mount.
- Rendering a root again from a source retires what its scripts registered with `tern.define`, `tern.on` and `tern.style`, so a live preview does not stack a behaviour, a listener and a stylesheet per edit; `tern.render` takes `scripts: false` to leave the scripts inert.
- An add-on listed twice (`data-use` and `:::use`) loads once; a `<script` inside a note script's text no longer shifts the positions of `script.document-write` diagnostics; a `data-css` stylesheet that fails to load is `addon.failed`; a capture write refused by a Trusted Types policy is said in the console.
- `data-nonce` is taken off the tag once read, and the tag's own `nonce` is used when `data-nonce` is absent.
- The support floor is stated (Chrome 86, Firefox 78, Safari 14) and guarded: an older browser is shown the source with a line saying why.

## 0.5.0 (2026-10-16)

- Inline constructs nest at most 1,000 deep; one past that is shown as its source text with `nesting.limit`. Ten thousand nested `**` used to parse into a tree that `JSON.stringify`, `tern.visit`, `tern.outline` and `tern.search` could not walk (a `RangeError`); those readers now keep their own stacks too.
- A reference's text and a toc entry copy at most 200 characters of their target, with an ellipsis; a 60 KB heading referenced 10,000 times used to make 600 MB of HTML and a `RangeError`. The emitter has an output budget too, `maxOutput` (64 M characters), past which the HTML stops with an `output.limit` diagnostic.
- Under `safe`, the attributes that drive the host page (`form`, `popovertarget`, `popovertargetaction`, `usemap`, `name`) are dropped too, attribute names are checked without case (a schema's `Href` passed), and a new `idPrefix` option of `tern.emit` and `tern.toHTML` keeps an untrusted root's ids and fragment links apart from the page's.
- `maxDepth` that is not a finite number of 1 or more means 64 (`'abc'` and `Infinity` used to lift the limit); a schema `label` function that throws is `addon.failed`, once per element, instead of escaping `tern.check` and `tern.toHTML`.
- A root rendered with `tern.render(el, text, {safe: true})` stays untrusted: it is marked `data-t-safe`, and a `tern.define` registered later, a later render of it without a source and a render of a root that holds it run no behaviour on it; a trusted source rendered into it makes it trusted again. `render` and `math` listeners get `{safe}` as a second argument. `tern.render` takes `idPrefix`.
- The KaTeX and MathML add-ons typeset an untrusted root with trust off whatever the page sets, with a copy of the macro table, and ignore its `:::macros`: with `trust: true` set for the page, a safe render of `\href{javascript:…}` used to make a live link, and a `\gdef` in it reached every later formula.

## 0.4.4 (2026-10-15)

- KaTeX add-on: `?trust=false` and `?strict=false` on the add-on's URL now mean false. They arrived as strings, which KaTeX read as true, so an author who turned trust off turned it on.
- Notes and search add-ons: an entry of `notes.json` or `search.json` whose URL is not a page on the file's own origin is left out, with a warning; a crafted file could make a `javascript:` or `data:` link. `index=` and `from=` must name `http(s)` URLs, and one that is not a URL at all is reported in place instead of leaving the box at "Indexing…" or the list empty.
- KaTeX add-on: a stylesheet that fails to load (a 404, an SRI mismatch, a `style-src` that omits the CDN) leaves math as its TeX source, with a warning, as a failed script does; it used to typeset into unstyled markup, each formula shown three times over.
- Mermaid add-on: `securityLevel` stays strict whatever the add-on's options say.
- The `:::use` scan (`src/use.js`, what the runtime and the tools read before parsing) handles CRLF text and closes the block only at `:::` or `:::/use`, as the parser does; `:::/meta` inside it used to end it early. The command line and the language server normalise line endings before scanning, so they were not affected by the CRLF part.
- Search: the snippet's word matching is linear in the text; its regex backtracked on a long unbroken token (about five seconds for 50,000 letters, once per hit in the search add-on and `tern search`). A word that stems to a matched stem (`studies` for `study`) is now marked too.
- Language server: a request with an id and no method, or a method that is not a string, is answered with `-32600` instead of being dropped, so a client does not wait forever; a `didChange` entry with a `range` is logged and ignored instead of being applied as the whole text (the server syncs full text).
- `tern index`: a tracked note with changes not yet committed is dated today, the day of the commit a hook is about to make, so that `--check` holds once it is committed; it was dated by its modification day, which could differ. A file git does not track is still dated by its modification time.
- Command line: output piped to a reader that closes early (`tern parse FILE | head`) ends the command quietly with exit 0; it died with an unhandled `EPIPE` and a stack trace, exit 1.
- Command line: what a note's add-on throws or logs is printed without terminal control characters (ESC, C1, the rest of C0 but tab and newline), in diagnostics, hints, `--json` and the console relay, so a note you have not read cannot retitle or clear the terminal. `?securityLevel=loose` on the tag used to win over the documented default, which made a `click` with a `javascript:` URL a live link.
- Project files: `SECURITY.md`, with private vulnerability reporting enabled on GitHub; `CONTRIBUTING.md`; an Editors section in the README. The README and the publishing page say that `tern.min.js` exists on jsDelivr, minified on request, and must not be used: the tools take a note only from a tag whose file is called `tern.js`.
- CI: the actions run on Node 24, the runner image is pinned to Ubuntu 24.04, and a tag's push no longer runs the CI workflow beside the release one. A lockfile, `npm ci`, `npm audit`, and caches for the smoke tests' CDN copies and browsers.

## 0.4.2 (2026-10-15)

- `tern index` writes `notes.json`, a catalogue of a folder's notes (path, title, description, date, headings, links), and `search.json`, the search index, beside them; in a git repository only tracked files are indexed, and a note with `robots: noindex` is left out.
- `addons/notes.js`: a `::notes` leaf that lists the catalogue's notes, newest first, with dates and descriptions.
- `::search{index=search.json}` reads the prebuilt index instead of fetching every note, and falls back to indexing in the browser when the file is missing or from another version series.
- `tern search --index=FILE` searches a prebuilt index; `:TernSearch` in tern.nvim passes `--index=` through.
- `tern.search.describe(head, ast)`: a note's title, description, meta, headings and links, for catalogues.

## 0.4.1 (2026-10-14)

## 0.3.0 (2026-10-12)

- Math is an add-on: `addons/katex.js` typesets with KaTeX and `addons/mathml.js` with Temml, each loaded from jsDelivr with SRI or from a local copy; the engine itself leaves formulas as TeX. A note that relied on built-in math now lists one of them. `tern build --math katex|mathml` pre-renders formulas.
- A safe render mode for untrusted text: `tern.toHTML(text, {safe: true})` and `tern.render(el, text, {safe: true})` escape raw HTML, neutralise running and navigating elements and attributes, and drop URLs that are not http(s), mailto or relative.
- The command-line tools run a note's own scripts and add-ons in a sandbox: a child process under Node's permission model and a sealed context with a time limit, so checking a note you have not read does not run it with your privileges; `--no-scripts` skips them.
- `tern check` and the language server check links between files: a target that does not exist, a fragment that names no id, a folder without an index.
- `tern mv FROM… TO` moves notes, files and folders and rewrites the links to and from them; the language server does the same when the editor renames a file (`workspace/willRenameFiles`).
- `tern check` reports a `tern.js` the note loads but that does not exist.
- `skills/tern-notes`: an agent skill for writing, checking and fixing notes with coding agents.
- Documentation redesigned (`docs/docs.css`), with two accuracy fixes from a prose audit; prose microtypography in the base stylesheet.
