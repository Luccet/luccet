:::meta description: The luccet object in node and in the browser: parse, transform, emit, toHTML, check, visit, outline, the schema registry, the runtime API and its events, luccet.config, the lifecycle, and the AST with its data.luccet fields. ::: ::site-nav # JavaScript API {#top} ::toc Everything Luccet does is on one object, `luccet`. In a browser it is `window.luccet`; under node it is what `require('./luccet.js')` returns. It has two halves: - **The engine** turns a note's source into an AST, computes its semantics and writes HTML. It is pure: no DOM, no I/O, the same output in node and in every browser. - **The runtime** renders a note in the page, runs DOM behaviours and fires events. It exists only in a browser. Under node its members are present but do nothing. This page is the reference for both, for the order in which the runtime does things, and for the AST the engine produces. It never rejects. Unlike `luccet.on('ready')`, it works whenever you await it, before or after the event. ```js await luccet.ready; document.querySelectorAll('main.luccet .t-math .katex').length; // the typeset formulas ``` It never settles under node, nor on a page where the runtime did not start ([When nothing starts](#no-start)). ### `luccet.diagnostics` {#diagnostics} The page's diagnostics, in one array that stays the same object for the life of the page: hold a reference and it stays current. - **At mount** it holds, sorted by position: - the runtime diagnostics found before the mount, at line 0, which therefore come first: [`doc.quirks`](diagnostics.html#doc-quirks), and [`addon.failed`](diagnostics.html#addon-failed) for an add-on that did not load or threw while it ran; - the note's parse and transform diagnostics, as [`luccet.check`](#check) returns them, including `addon.failed` for a registered transform that threw. - **Later** runtime diagnostics are appended as they happen: [`script.document-write`](diagnostics.html#script-document-write) and [`script.domcontentloaded`](diagnostics.html#script-domcontentloaded) while the note's scripts run. (The engine renders no math, so a math add-on reports a formula it cannot typeset to the console, not here.) They concern the page's note: one about an element that another `luccet.render(root, source)` call rendered only fires the event. Each diagnostic the runtime reports itself, early or late, also fires the [`diagnostic`](#on) event; those of the parse and the transforms do not. - **`luccet.render(main, source)`** replaces the contents with the new note's diagnostics, keeping the line-0 ones. - **On a built page** it holds the build's diagnostics, read from the page, then an `addon.failed` for each add-on script that failed to load or threw while it ran. Each entry has the [shape of a diagnostic](#check). Where both set a key, the attribute wins. ```html ``` On that page, once luccet.js has started: ```js luccet.config; // → { use: { katex: { macros: { '\\R': '\\mathbb{R}' } }, // theorems: { labels: 'de' }, theme: { dark: '' } }, // lang: 'en', nonce: 'abc', diagnostics: false, quiet: false } ``` - **When.** `luccet.config` is filled once, when luccet.js starts. So `window.LUCCET` must be set by a script in the head, before the luccet.js line; setting it later does nothing. - **What is copied.** Every key of `window.LUCCET` is copied into `luccet.config`, including keys Luccet does not use. An add-on can read its own settings from there. - **`addonTimeout`** (milliseconds, 12 000 by default) is how long the mount waits for an add-on still loading once the note has arrived ([Waiting](#capture)). - **`holdOver`** (characters, 30 000 by default) is the note size from which the mount holds the top-level blocks out of view with `content-visibility: auto`, so a long note paints its first screen without laying out the rest ([Performance](publishing.html#performance)); `0` never holds. - **Booleans.** For `data-diagnostics` and `data-quiet`, the values `false`, `0`, `off` and `no` (in any case) mean false; any other value, or none, means true. Its value is a list of URLs, separated by spaces, resolved against the page; a [`:::use` block](syntax-blocks.html#use) at the top of the note lists more, one or more per line, loaded after the tag's. An entry ending in `.css` (before its query) is a stylesheet, linked in its place in the [cascade](#style); any other is a script. Scripts are fetched in parallel and run in the order listed, and the note mounts only once every entry has loaded or failed. **KaTeX options.** The [`katex.js` add-on](addons.html#katex) reads `luccet.config.use.katex` and passes every key except `displayMode` and `throwOnError` to KaTeX: `macros`, `trust`, `strict`, `output`, `leqno` and the rest. `throwOnError` is always true, so a formula KaTeX rejects keeps its TeX, and the add-on warns in the console rather than reporting a diagnostic. `macros` is copied into one table that every formula shares; the `:::macros` blocks of the note are defined into it first. A copy of KaTeX of your own is `addons/katex.js?base=URL`, not a config key.
