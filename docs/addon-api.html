How an add-on loads and takes options, what it registers, the lifecycle, math, foreign content and the command line. ::: ::site-nav # Writing an add-on {#top} ::toc An add-on is a script or a stylesheet that a note lists in `data-use` or a `:::use` block, to add what the engine leaves out: names and their meaning, behaviour, a look. This page is the contract between the engine and an add-on: everything an add-on may rely on, in the browser and under node, which only a major release may break. [Add-ons](addons.html#top) lists Luccet's own; the reference for each call is on [Vocabulary and behaviour](schema.html#top) and the [JavaScript API](api.html#runtime). ## The contract's number {#api} `luccet.api` is the number of this contract: `2`. It changes only when the contract breaks, which only a major release may do, and not at every major one: Luccet 3 may keep it. What a minor release adds, such as a member, an event or a schema field, an add-on finds by feature detection (`typeof luccet.x === 'function'`). An add-on checks the number before it registers anything, and its page says which one it needs: ```js if (window.luccet.api !== 2) throw new Error(`needs the add-on API 2; this luccet.js has ${window.luccet.api}`); ``` Thrown while it loads, that is [`addon.failed`](#addon-failed) with the message, in the browser and in `luccet check`, and the note renders without the add-on. luccet.js 1.x has no `luccet.api`. ## Loading {#loading} An add-on is listed in `data-use` on the luccet.js tag: ```html ``` or in a [`:::use` block](syntax-blocks.html#use) at the top of the note, one or more per line: ```html :::use lib/callout.js lib/theme.css ::: ``` ### Listing add-ons {#data-use} - **The list** is space-separated on the tag, and one or more entries per line in the block. Each entry is a URL, relative to the page like any `src`. - **Two places, one list.** `data-use` is fine for a single add-on; `:::use` is the readable form for several. Both are honoured and merge: the tag's entries load first, then the block's, in order. - **`:::use` must lead the note:** at the top level, before any content; only `:::meta`, blank lines and other `:::use` blocks may come before it. luccet.js reads it from the file as it arrives, so its add-ons start loading almost as early as the tag's, and the tools read it before they analyse. One anywhere else gets [`use.late`](diagnostics.html#use-late) and is ignored. The block emits nothing. - **Stylesheets and scripts.** An entry whose path ends in `.css` is a stylesheet; anything else is a script. - **Order matters.** Scripts run in the order listed, so a later add-on sees an earlier one's entries and can change them. Stylesheets cascade in the order listed: a theme listed after an add-on wins at equal specificity. - **Under node**, the command line reads the entries the same way: every entry that does not end in `.css` is run as a classic script, `.mjs` or no extension included. One that does not parse as a classic script, or names a directory, is `addon.failed` ([Under node](#node)). ### Options in the query string {#use-options} An add-on takes options from its URL's query string, in `luccet.config.use`: ```html ``` ```js luccet.config.use.callout // {collapse: 'all', accent: 'teal'} ``` A `:::use` entry takes the same query string, `lib/callout.min.js?collapse=all&accent=teal`, with `&` written as it is: the block's body is verbatim. - **The key** is the file name without its directory, `.min`, and `.js`, `.mjs` or `.css`: `lib/callout.min.js` is `callout`. - **Every entry** gets an object, empty when there is no query. - **Values** are strings. A key without `=` gets `''`. - **Defaults.** `window.LUCCET.use = {callout: {collapse: 'none'}}` gives defaults; the query string wins key by key. - **`&`** is the strict HTML spelling of `&` in an attribute; both work. - **Under node** `luccet.config.use` is built the same way, from `window.LUCCET.use` and the query strings of `data-use` and `:::use`, so `luccet check` and `luccet build` see the options the browser sees ([Under node](#node)). ### How they load {#addon-loading} 1. When luccet.js starts, it adds a preload for every script add-on, then appends them all at once: they **download in parallel** and **run in the order listed**. Stylesheets are added as links, in order. 2. The note is rendered once the document is parsed and **every add-on has loaded or failed**, or 12 seconds after the document was parsed, whichever comes first ([the lifecycle](api.html#capture)). 3. So an add-on runs **before the mount**. `window.luccet` exists; `window.LUCCET.schema` is not applied yet; the note's elements do not exist yet. An add-on therefore registers things, for the runtime to apply when the note is rendered ([What an add-on registers](#registry)). It does not look for the note's elements itself: they are not there yet. ### When an add-on fails {#addon-failed} **`addon.failed`** is an error at the luccet.js line. The note always renders. It is reported when: - a script or stylesheet does not load (a wrong path, a network error): the note renders without it; - a script throws while it runs: the note renders with what the add-on registered before the error, and the browser's console shows where it threw; - a transform the add-on registered throws when it runs: that transform is skipped ([Custom transforms](schema.html#transforms)). The command line and the language server report the same cases, and a few of their own: - a missing file, or a directory; - a script that does not parse as a classic script; - a script that throws under node, where the browser's globals are stand-ins ([Under node](#node)). **A remote add-on** (`https://…`) is not loaded under node. That is **`addon.remote`**, an info at the luccet.js line: names it declares are unknown to `luccet check`, which does not fail because of it. `luccet build` warns about it: the page it writes uses those names without their schema entries. **Diagnostics:** [`addon.failed`](diagnostics.html#addon-failed), [`addon.remote`](diagnostics.html#addon-remote). ## A complete add-on {#callout-addon} This add-on declares three callouts, `note`, `tip` and `warning`, with labels in three languages, a stylesheet, and a behaviour that folds a callout away. ```js [callout.js, a complete add-on]{#lst-callout} // callout.js: callouts for Luccet notes, in English, German and French. // // (function () { 'use strict'; const luccet = window.luccet; if (luccet.api !== 2) throw new Error(`needs the add-on API 2; this luccet.js has ${luccet.api}`); // 1. Vocabulary: three containers with a label in three languages. const labels = { note: { en: 'Note', de: 'Hinweis', fr: 'Remarque' }, tip: { en: 'Tip', de: 'Tipp', fr: 'Astuce' }, warning: { en: 'Warning', de: 'Warnung', fr: 'Attention' }, }; for (const name of Object.keys(labels)) { luccet.block(name, { tag: 'aside', class: 'callout', attrs: { role: 'note' }, label: labels[name], dom: collapsible, }); } // 2. Look: keyed on the classes, never on the tag. luccet.style(` .luccet .callout { border-inline-start: 4px solid var(--callout, var(--t-link)); background: var(--t-soft); padding: .6rem 1rem; border-radius: 6px; } .luccet .callout.tip { --callout: #2f8a46; } .luccet .callout.warning { --callout: var(--t-warn); } .callout-toggle { margin-inline-start: .5rem; font: inherit; cursor: pointer; } @media print { .callout-toggle { display: none; } } `); // 3. Behaviour: a callout with data-collapse, or every callout with // ?collapse=all, gets a button that folds its body away. const options = luccet.config.use.callout || {}; // absent when the add-on is not listed function collapsible(el) { const title = el.querySelector(':scope > .t-title'); if (!title || !(options.collapse === 'all' || el.hasAttribute('data-collapse'))) return; const button = document.createElement('button'); button.type = 'button'; button.className = 'callout-toggle'; button.setAttribute('aria-expanded', 'true'); button.textContent = 'Hide'; button.addEventListener('click', () => { const open = button.getAttribute('aria-expanded') === 'true'; button.setAttribute('aria-expanded', String(!open)); button.textContent = open ? 'Show' : 'Hide'; for (const child of el.children) if (child !== title) child.hidden = open; }); title.append(button); } })(); ``` A note that uses it: ```html :::warning[Strom]{#w data-collapse} Erst den Stecker ziehen. ::: ``` The engine writes this (as `luccet build` shows it, without positions), and the behaviour then adds the button to the title: ```html
Warnung Strom

Erst den Stecker ziehen.

``` What each part does: - **The wrapper** keeps the add-on's names out of the page's globals, and reads `window.luccet`, which luccet.js defined before any add-on runs. It checks [the contract's number](#api) first. - **The vocabulary.** The label map picks "Warnung" from `` ([Labels in other languages](schema.html#languages)). `class` and `attrs` give every callout the class `callout` and `role="note"`. - **The look.** `luccet.style` puts the rules at this add-on's place in the cascade and adds the page's nonce. Most of the rules use luccet's custom properties, so they follow dark mode ([Styling](schema.html#styling)). - **The behaviour** reads a per-element option from a `data-*` attribute (`{data-collapse}`), and a per-note option from the query string. ### Guidelines {#addon-guidelines} - **Register everything while the script runs.** The mount comes after; nothing registered later applies to the note until the next render. - **Key CSS and behaviours on the class or `data-t`, never on the tag.** An author can change the tag with `{tag=…}`. - **Use `luccet.style`** rather than adding your own `
